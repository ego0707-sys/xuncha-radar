# 巡查雷达 v0.2 · 双模式 Agent 第一版

面向内容生态治理的开源情报 Agent。产品围绕两种真实工作方式设计：

- **日常自主巡查**：不依赖用户先知道关键词，从近期权威治理重点、境内外弱信号、新实体和新话术中主动提出风险命题；
- **专题线索追踪**：围绕已知事件、账号、组织、话术或风险机制，持续扩展源头、传播链和境内落地。

两种模式共用一条可审计研究链路：

> 权威规则 → 弱信号发现 → 实体溯源 → 境内落地 → 证据核验 → A/B/C 分层

## 第一版包含

- 日常自主巡查、专题线索追踪两个独立任务模式；
- Kimi K3 多轮 Agent、内置联网搜索与证据二次核验；
- 任务模式决定不同的研究规划，界面不是简单改名；
- A 级可直接核验、B 级有价值线索、C 级观察池；
- 对“完整覆盖、部分覆盖、采集失败、本轮未覆盖”进行区分；
- 历史任务、判断规则、研究轨迹和人工反馈；
- 前后端一体部署到 Render，不依赖 `workers.dev` 或 `chatgpt.site`；
- API Key 由每台团队电脑首次使用时填写，只保存在当前浏览器会话，服务端不落盘。

第一版不包含平台内部完整搜索、评论区批量采集、账号关系图谱和无人值守定时调度。它先解决“发现什么风险、为什么值得查、原始内容在哪里”的问题；扩展评论区样本和最终定性仍由人工完成。

## 项目结构

```text
app/                    双模式巡查工作台前端
radar_engine/           多轮研究 Agent、分级、核验与失败状态
render_app.py           Render API 与静态文件服务
Dockerfile              前后端一体化构建
render.yaml             Render 免费 Web Service 配置
```

## Render 部署

仓库包含 `render.yaml` 和 `Dockerfile`。在 Render 中连接本仓库并创建 Blueprint 或 Web Service 后，会自动构建前端并启动服务端 Agent；健康检查路径为 `/healthz`。

## 无需银行卡的临时测试

[在 GitHub Codespaces 中启动巡查雷达](https://codespaces.new/ego0707-sys/xuncha-radar?quickstart=1)

个人 GitHub 账号包含每月免费 Codespaces 额度，创建时无需提供付款信息。首次启动会自动安装依赖、构建前端并运行完整服务；构建完成后浏览器会打开转发的 10000 端口。该方式适合第一版效果验证，Codespace 停止后测试网址也会暂停。

## 本地运行一体化版本

```bash
npm ci
npm run build:render
PYTHONPATH=radar_engine/src PORT=10000 python render_app.py
```

然后打开 `http://localhost:10000`。仅运行 Next.js 开发服务器只能预览界面，无法执行服务端调查。

首次打开页面时，点击“设置密钥”，粘贴 Moonshot 开放平台 API Key。网站后端会验证该 Key 确实可以使用 `kimi-k3`，验证通过后才允许开始巡查；系统不会降级到 K2。

密钥保存在浏览器 `sessionStorage`，关闭当前浏览器会话后失效；不会写入 GitHub 源码、服务端文件或网页导出的诊断文件。

巡查固定使用 `kimi-k3`。Kimi 负责研究决策和检索，服务端确定性代码负责重复检索阻断、URL 安全检查、页面核验、A/B/C 材料分级以及失败状态管理。没有配置密钥、检索失败或证据不足时，系统不会生成模拟线索。

## 当前检索边界

第一版使用 Kimi K3 内置联网搜索发现线索，可以覆盖搜索服务能够访问的公开页面，但不能承诺完整检索抖音、小红书、B站、贴吧等平台内部内容。页面返回“0条”时，会同时展示采集状态；没有真实可核验链接的内容不会进入线索区。

## 使用提醒

测试版最多同时运行两个调查任务；单次最多 10 次检索、8 轮研究、10 个输出主题。模型调用费用由当前浏览器会话中填写的密钥所属账户承担。关闭浏览器或点击“清除本机密钥”即可移除密钥。
