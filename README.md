# 巡查雷达 v0.1 · Render 验证版

面向内容生态治理的开源情报调查工作台。第一版只验证一条核心链路：

> 任意自然语言巡查需求 → 动态任务说明 → 调查查询 → 公开网页检索 → 语境排除 → 可核验线索

## 第一版包含

- Kimi、DeepSeek、豆包三种模型入口，模型可以替换；
- 通用调查任务编译器，不按宗教、谣言、未成年人等主题硬编码；
- Render 服务端 Kimi K3 多轮 Agent、内置联网搜索与证据二次核验；
- 对“完整覆盖、部分覆盖、采集失败、本轮未覆盖”进行区分；
- 任务说明、查询策略、证据卡、AI研判和执行日志；
- 前后端一体部署到 Render，不依赖 `workers.dev` 或 `chatgpt.site`；
- API Key 由每台团队电脑首次使用时填写，只保存在当前浏览器会话，服务端不落盘。

第一版不包含平台内部完整搜索、评论区采集、长期证据库、账号关系图谱和持续监测。这些能力将在验证核心链路有效后逐步接入。

## 项目结构

```text
app/                    调查工作台前端
radar_engine/           多轮研究 Agent、分级、核验与失败状态
render_app.py           Render API 与静态文件服务
Dockerfile              前后端一体化构建
render.yaml             Render 免费 Web Service 配置
```

## Render 部署

仓库包含 `render.yaml` 和 `Dockerfile`。在 Render 中连接本仓库并创建 Blueprint 或 Web Service 后，会自动构建前端并启动服务端 Agent；健康检查路径为 `/healthz`。

## 本地运行一体化版本

```bash
npm ci
npm run build:render
PYTHONPATH=radar_engine/src PORT=10000 python render_app.py
```

然后打开 `http://localhost:10000`。仅运行 Next.js 开发服务器只能预览界面，无法执行服务端调查。

首次打开页面时，点击“设置 Kimi Key”，粘贴 Moonshot 开放平台 API Key。网站后端会验证该 Key 确实可以使用 `kimi-k3`，验证通过后才允许开始调查；系统不会降级到 K2。

密钥保存在浏览器 `sessionStorage`，关闭当前浏览器会话后失效；不会写入 GitHub 源码、服务端文件或网页导出的诊断文件。

调查固定使用 `kimi-k3`。Kimi 负责研究决策和检索，服务端确定性代码负责重复检索阻断、URL 安全检查、页面核验、A/B/C 材料分级以及失败状态管理。没有配置密钥、检索失败或证据不足时，系统不会生成模拟线索。

## 当前检索边界

第一版使用 Kimi K3 内置联网搜索发现线索，可以覆盖搜索服务能够访问的公开页面，但不能承诺完整检索抖音、小红书、B站、贴吧等平台内部内容。页面返回“0条”时，会同时展示采集状态；没有真实可核验链接的内容不会进入线索区。

## 使用提醒

测试版最多同时运行两个调查任务；单次最多 10 次检索、8 轮研究、10 个输出主题。模型调用费用由当前浏览器会话中填写的密钥所属账户承担。关闭浏览器或点击“清除本机密钥”即可移除密钥。
